## 3. Migrations and registry on the integrated tree
- The release line adds 5 migrations numbered `1790030000000` … `1790030400000` (finance ×3, core seed, procurement). The org-engine migrations are `1790021000000` … `1790021600000` — **older timestamps than the release line's**. In the TypeORM version used here (0.3.31) the "pending migration older than the newest executed" check is **disabled** in `MigrationExecutor` (the throwing lines are commented out), so a Company already migrated to the release line would still run the 7 org-engine migrations. This is a source reading, **not yet an executed proof**; the integrated-tree verification must include: (a) a database at the release-line head that then receives the 7 migrations, (b) the same from empty, (c) the release-engine preflight/registry spec.
- `undoLastMigration` reverts the migration with the **newest timestamp** first; on the integrated tree that is a release-line migration, not an org-engine one. The up/down check therefore has to be redesigned for that tree (undo the newest N regardless of origin, or run down only for the org-engine set on a database where it is the newest set) and its limits restated; the negative-control test cut-off (`2d4eb06`) must be re-evaluated against the new newest migrations.
