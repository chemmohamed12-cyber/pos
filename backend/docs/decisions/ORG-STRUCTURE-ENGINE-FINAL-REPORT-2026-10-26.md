- **Reversibility limits (stated, not hidden):** the cycle is **schema-reversible, not data-reversible**. After down → up: (a) the stamped `branchOrgUnitId` / `vehicles.orgUnitId` values are **lost** (columns return NULL — a backfill/re-stamp is needed); (b) **archived org units come back as `active`** (the archive state lived in the dropped column); (c) `org_migration_log` rows are **lost** (table dropped); (d) the parent FK **stays `RESTRICT`** after down (deliberate: re-introducing `CASCADE` would be the unsafe direction), so `down` is not a byte-for-byte restoration of the pre-migration FK. Therefore on any Company holding stamped or archived data the rollback path is the release engine's backup restore, not `down` — and `down` must never be used as a routine undo there.
