# D-12 / D-13 — توضيحات خطة T-01…T-12، تعريف R1–R10، وتغطية الحارس

الحالة: **مسودة للاعتماد — لا تنفيذ.** الأرقام أهداف مقترحة، لا معايير نهائية؛ «تجميد النتائج المتوقعة» يتم بعد اعتماد هذه الوثيقة وقبل أي تشغيل أعمال. لا يُغلق TEST-01/TEST-02 بنجاح هذه الاختبارات المحلية.

## 1. تعريفات مشتركة (تُجمَّد قبل التنفيذ)
**«لا أثر جزئي» (T-01/T-02 وكل حالة رفض):** رفض HTTP/الخدمة لا يكفي. تُؤخذ **بصمة** (md5 للصفوف المرتبة، نمط `security-mutation-verification.js`) قبل وبعد لمجموعة الجداول التالية، ويجب أن تتطابق تمامًا باستثناء ما يُصرَّح به صراحةً:
`stock_movements, stock_reservations, inventory_valuation_state, inventory_valuation_movements, accounting_financial_events, accounting_journal_entries, accounting_journal_lines, event_outbox, customer_ledger_entries, supplier_ledger_entries, treasury_transactions, customer_payments, supplier_payments, warehouse_transactions (+lines), process_instances, process_transition_records, idempotency_records`.
**الاستثناء المصرح به الوحيد:** `audit_records` قد يزيد بسجلات رفض موثقة بالعدد المتوقع فقط (يُتحقق من العدد والمحتوى، وسلامة السلسلة `verifyChain`).
**الرصيد السالب:** غير مسموح في أي حالة (`SUM(quantity) ≥ 0` لكل زوج مستودع/منتج، ورصيد الخزينة ≥ 0) إلا عبر سيناريو مُعلن صراحةً كإثبات للعيب (T-09) ويُسجَّل STOP.

## 3. تعريف المصالحات R1–R10 (الاستعلامات ومصدر كل رقم متوقع)
قاعدة عامة: الأرقام المتوقعة تأتي من **oracle مستقل داخل الاختبار** (سجل JS للعمليات المقبولة يحسب الأرصدة بنفسه) أو من مقارنة طرفين مستقلين في النظام، وليس من خدمة المصالحة نفسها. التسامح: تساوٍ تام عشري (4 منازل أساس). أي فرق = يُصنَّف ويُفسَّر؛ **فرق غير مفسر ⇒ STOP**. تفسير مسموح به فقط إذا ذُكر مسبقًا في سجل «الاستثناءات المعلنة» لذلك السيناريو (مثل الحدث المصنَّع في سيناريو مرتجعات).
| R | الطرفان | استعلام القراءة (مختصر) | مصدر المتوقع |
|---|---|---|---|
| R1 | أرصدة المخزون ↔ حركات المخزون | `SELECT "warehouseId","productId",SUM(quantity) FROM stock_movements GROUP BY 1,2` ↔ `getOnHand` ↔ **oracle JS** (يجمع الحركات المقبولة وحده)؛ + `R1b`: لا قيمة < 0 | oracle |
| R2 | تقييم المخزون ↔ الدفتر ↔ GL | `inventory_valuation_state.onHandQuantity` = R1؛ `totalValueBase` = Σ `inventory_valuation_movements.valueDeltaBase`؛ Σ `totalValueBase` = رصيد حسابات `controlFunction='inventory'` (Σ debitBase−creditBase) **مطروحًا منه الاستلامات التي ترحّل بأحداث GRNI/افتتاحية خارج السيناريو** (استثناء معلن) | oracle للتكلفة المتوسطة المتحركة |
| R3 | دفتر العملاء ↔ GL (AR) | Σ(`customer_ledger_entries`: debit +amount / credit −amount) ↔ Σ(debitBase−creditBase) لحسابات `controlFunction='ar'` (اصطلاح الإشارة يُجمَّد من اختبار on-account #6 القائم) | oracle المبيعات/الدفعات |
| R4 | دفتر الموردين ↔ GL (AP) | `supplier_ledger_entries` (entryType، direction، amount) ↔ حسابات `controlFunction='ap'` | oracle المشتريات |
| R5 | الخزينة ↔ GL البنك | `treasury_transactions`: `cash_in/transfer_in` موجب وغيرها سالب لكل حساب ↔ حسابات `controlFunction='bank'` المربوطة | oracle |
| R6 | توازن القيود | `SELECT journalEntryId FROM accounting_journal_lines GROUP BY 1 HAVING SUM("debitBase")<>SUM("creditBase")` = ∅ | قاعدة |
| R7 | حركة ↔ حدث ↔ قيد | لكل حركة نوعها ذو `glKind` (dispatch/adjustment/return_in/افتتاحي/يدوي): حدث واحد بمفتاح `inventory:movement:<id>:recorded`؛ كل حدث POSTED له `journalEntryId`؛ لا قيد بلا حدث مصدر؛ لا حدث PENDING/REJECTED غير مصنَّف | قاعدة + قائمة استثناءات معلنة |
| R8 | GRNI / WIP / PPV / VAT | تشغيل خدمات المصالحة القائمة (`accounting_*_reconciliation_runs`) **ومقارنتها** باستعلام SQL مستقل لكل حساب تحكم | oracle |
| R9 | العكس والمرتجعات والتسويات | بعد العكس تعود الأرصدة (R1–R5) إلى قيمة ما قبل العملية + الأثر الصافي المتوقع (oracle) | oracle |
| R10 | لا أثر للعمليات المرفوضة | البصمة قبل=بعد (§1) ثم R1–R7 ثابتة | بصمة |
مخرج R: جدول لكل مقارنة (الطرفان، القيمتان، الفرق، التصنيف/التفسير، الاستعلام الدقيق، commit، القاعدة)، وملف خام محفوظ خارج القاعدة قبل أي تنظيف.
