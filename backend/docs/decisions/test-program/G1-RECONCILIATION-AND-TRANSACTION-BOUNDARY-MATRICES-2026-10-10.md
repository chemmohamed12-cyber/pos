# G1 — مصفوفتا المصالحة المالية/المخزنية وحدود المعاملات (مسودة)

الحالة: **مسودة للاعتماد — بلا تنفيذ**. تُملأ خانات «الملاحظ» من القراءة فقط؛ كل خانة «يُحدَّد» تحتاج قراءة كود/تجربة قبل الاعتماد.

## 1. مصفوفة المصالحة المستقلة (تقرير مستقل، لا سيناريو)
قاعدة: **لا فروق غير مفسرة.** تطابق بصمات الجداول لا يثبت صحة الأرصدة المحاسبية. يُنتج التقرير بعد كل جولة G1/G2/G6 على قاعدة التجربة ويُحفظ خارجها.
| # | المقارنة | الطرفان | قاعدة القبول | ما يوجد اليوم | الحالة |
|---|---|---|---|---|---|
| R1 | أرصدة المخزون = مجموع الحركات | `stock`/on-hand مقابل Σ `warehouse_transactions`/movements لكل (منتج، مستودع) | مساواة تامة | `getOnHand` يُستخدم في اختبارات العزل؛ لا تقرير شامل | غير مغطى كمصالحة |
| R2 | مجموع تقييم المخزون = حساب 1120 (GL) | valuation مقابل دفتر الأستاذ | فرق = 0 أو مفسَّر | بند 15 في `returns-accounting` (سيناريو واحد)، `grni/wip-reconciliation` | جزئي |
| R3 | الدفتر الفرعي للعملاء = حساب AR (1110) | `customer_ledger` مقابل GL | = 0 | غير مكتشف كمصالحة | يُحدَّد |
| R4 | الدفتر الفرعي للموردين = AP | AP subledger مقابل GL | = 0 | غير مكتشف | يُحدَّد |
| R5 | رصيد الخزينة/البنك = حركات الخزينة = GL (1101/1102/…) | treasury مقابل GL | = 0 | `getAccountBalance` في اختبارات العزل | جزئي |
| R6 | كل مستند مرحَّل له قيد متوازن (Dr=Cr) | journal_entries | Σ مدين = Σ دائن لكل قيد | بند 15 returns | جزئي |
| R7 | كل حركة مخزنية ماليّة لها حدث/قيد (لا حركة بلا قيد ولا قيد بلا مصدر) | `financial_events` مقابل الحركات | كل حدث POSTED أو REJECTED بسبب معلوم؛ لا يتيم | event engine + closing audit | جزئي |
| R8 | GRNI/WIP/PPV/VAT مقابل مستنداتها | reconciliations القائمة | = 0 | `grni/wip-reconciliation.spec` (U) | جزئي |
| R9 | المرتجعات والعكس والتسويات تُرجع الأثر كاملًا | قبل/بعد | الأرصدة تعود للحالة المتوقعة | `returns-accounting`, void invoice | جزئي |
| R10 | لا أثر لعملية مرفوضة | بصمات + R1–R8 قبل/بعد | لا تغيير | نمط md5 في `security-mutation-verification.js` | سكربت يدوي |
مخرج التقرير: جدول لكل مقارنة (الطرفان، القيمتان، الفرق، التفسير، الدليل، commit، قاعدة الاختبار).

## 2. مصفوفة حدود المعاملات
المبدأ: لكل عملية حرجة نحدد (أ) ما يجب أن يكون ذريًا في معاملة DB واحدة، (ب) ما يُترك لحدث/مهمة لاحقة، (ج) كيف تتم المصالحة لو فشل (ب)، (د) اختبار يثبت ذلك.
| العملية | ذري (معاملة واحدة) — الملاحظ | لاحق (حدث/مهمة) | مصالحة عند الفشل | اختبار حالي |
|---|---|---|---|---|
| استلام مستودع/GR | المستند + حركة المخزون + التقييم (يُقرأ: `transition('submit')` يرحّل ويكتب الحركة) | قيد GL عبر Event Engine (outbox) | حدث REJECTED أو معلّق قابل لإعادة المحاولة؛ closing audit | `warehouse-transactions`, `event-engine` (E) — فشل المنتصف لم يُختبر |
| شحن/صرف بيع | الحركة + التقييم | قيد COGS عبر حدث | كما أعلاه | يُحدَّد |
| فاتورة بيع | AR + outbox في نفس معاملة الترحيل (`invoices.company-isolation`: «posting writes the AR debit and the outbox event») | قيد GL | event engine | جزئي |
| تحصيل/دفعة على الحساب | رفض قبل التعديل عند فشل الشروط؛ التنفيذ: حركة الخزينة + دفتر العميل | قيد GL (حدث) | REJECTED fail-closed (`11b`) | `on-account-payment` (E) |
| فاتورة مورد/VOID | VOID يعكس الدفتر وGL وPPV والحالة معًا («ذري») | — | — | `supplier-invoice-ppv-vat` بند 7 (E) |
| مرتجع بيع/شحنة | المرتجع + إعادة المخزون بالتكلفة الأصلية + عكس الفاتورة | قيد GL (حدث) | رفض قبل التعديل لو الإعداد مفقود؛ REJECTED وقت الحدث | `returns-accounting` (E) |
| أمر تصنيع (صرف مواد) | الحركة + التقييم | قيد WIP | deadlock retry | `f03-deadlock-retry` (U) |
| إنشاء شركة/تزويد قاعدة | Company registry + تخصيص قاعدة؛ تزويد قابل للاستئناف | ترحيلات الشركة | retry-provisioning | `pool.full-flow.real-pg` (E) |
| نشر إصدار | تبديل الشرائح (slots) بعد فحص البيئة | جاهزية HTTP → تراجع تلقائي | LKG + reconcile لعملية متوقفة | `release-execution-*` (U) |
| تدقيق | أخذ قفل advisory ثم قراءة آخر hash وكتابة السجل في نفس المعاملة | — | — | `audit-chain-concurrency` (E) |
| حجز مخزون عند إنشاء أمر بيع | يُحدَّد (الكود يذكر تراجع الإضافة عند نقص) | — | — | غير مغطى |
| اعتماد (Approval Engine) | يُحدَّد | تنفيذ الإجراء بعد الاعتماد | انتهاء صلاحية/scheduler | يُحدَّد |
**المطلوب قبل الاعتماد:** تعبئة كل خانة «يُحدَّد» بقراءة الكود وتحديد النقاط التي يمكن أن تُنتج «نصف عملية» (حركة بلا قيد، قيد بلا حركة، تحصيل بلا تطبيق)، ثم تحويل كل نقطة إلى سيناريو G2.
